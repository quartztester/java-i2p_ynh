La console est derrière le SSO. Par défaut ce routeur est floodfill ; pour
rétrograder en simple relais : Config → Router manager.

## Tunnels clients (proxys eepsite)

Par conception, ce paquet fournit un jeu de clients minimal orienté relais : la console du routeur et le pont SAM, rien d'autre — pas de proxy HTTP/SOCKS, pas d'eepsite. Le **pont SAM est activé par défaut sur `127.0.0.1:7656`** pour que les apps locales (qBittorrent I2P, autres clients SAM) fonctionnent sans étape manuelle ; la distribution enregistre le client SAMBridge avec `startOnLoad=false`, et les scripts install/upgrade le passent à `true` dans `clients.config.d/01-net.i2p.sam.SAMBridge-clients.config` (édité pendant que le routeur est arrêté). Pour le désactiver, mettez `startOnLoad=false` dans ce fichier et redémarrez, ou basculez-le depuis la page de configuration des clients de la console. Les tunnels clients s'ajoutent via le *Hidden Services Manager* de la console (I2P tunnels → Create) ; ils sont stockés dans `i2ptunnel.config.d/` dans le répertoire de données, donc conservés aux mises à jour et inclus dans les sauvegardes. Défauts amont si vous recréez les proxys à la main : proxy HTTP 4444, proxy HTTPS 4445, SAM 7656, eepsite 7658. Si l'app `i2pd` tourne sur le même serveur, éloignez ses proxys/SAM de ces numéros — ses questions d'installation servent précisément à cela (les deux routeurs utilisent 7656 par défaut ; celui installé en second bascule automatiquement sur 7666 — `yunohost app setting java_i2p port_sam`).
